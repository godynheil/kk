# Git Wrapper Checklist

## Critical wrappers

- `kk init` instead of `git init`
- `kk clone <remote-spec> [<dest>]` instead of `git clone` — downloads a
  project from a kk remote backup and reconstructs a local working copy.
  Remote spec formats:
  - `local:/path/to/remote-root/ProjectName`
  - `rclone:<rclone-remote>:<path>/ProjectName`
  - `drive:<drive-folder-id>/ProjectName`

  The `drive:` **folder-id** is generated by Google Drive and stored
  automatically in `.kk/config.json` when Machine A runs `kk setup gdrive`.
  Machine A prints it after setup and it can also be read with
  `kk remote list --json` (`drive_folder_id` field). Machine B must
  run `kk setup gdrive --auth-only` first (no repo needed) to save
  credentials before cloning.

  What it does in order:
  1. Checks remote accessibility (`driver.Check()`).
  2. Reads `<ProjectName>/.kk/repo.json` to verify the project
     exists and recover the original `repo_id`.
  3. Downloads the full project mirror into `<dest>/`.
  4. Creates `.kk/objects/`, `.kk/tmp/`, `.kk/logs/`, `.kk/git/`.
  5. Runs `git init` inside `.kk/git/`.
  6. Writes a fresh `.kk/config.json` (the downloaded one belongs to another
     machine) registering the clone source as remote `origin`.
  7. Restores `.kk/repo.json` with the recovered `repo_id`.
  8. Stages all files and creates an initial `kk clone: initial snapshot` commit.
  9. Registers the project in the local registry.
  10. With `--pull`: materialises all pointer files immediately.
- `kk add` instead of `git add`
- `kk commit` with staged large-file validation
- `kk push` — before running `git push`, does three things in order:
  1. **Collision guard** — reads `.kk/repo.json` from the remote project mirror
     and aborts if it belongs to a different `repo_id`.
  2. **Project file sync** — mirrors files to
     `<remote-root>/<ProjectName>/`. Two modes:
     - Default: syncs only files tracked in current HEAD commit,
       plus `.kk/repo.json`, `.kk/config.json`, `.kk/tracks.json`
     - `--sync-working-dir`: syncs the entire working directory (respecting `.kkignore`)
  3. **Object upload** — uploads any large-file objects not yet present on the
     remote into `<remote-root>/<ProjectName>/objects/`.
- `kk pull` with object health check after Git pull
- `kk diff --code` to avoid pointer noise
- `kk diff --assets` later for asset pointer summaries
- `kk checkout` / `kk switch` auto-materialize pointer files after a successful switch
- Dirty materialized file safety before branch changes is still pending
- `kk reset` / `kk clean` safety later

## Safe pass-through commands

- `kk log`
- `kk branch`
- `kk show`
- `kk config`
- `kk rev-parse`

All pass-through commands still inject:

```bash
git --git-dir=.kk/git --work-tree=.
```


## Object deduplication and retention wrappers

These wrappers protect content-addressed large objects across branches and tags.

```bash
kk objects live [--json]
kk objects refs <sha256> [--json]
kk objects prune [--dry-run] [--json]
```

Required behavior:

```text
Same SHA-256 object is uploaded once per remote.
Upload skips if the target remote already has the SHA-256 object.
Local prune only deletes objects that no reachable commit references.
Remote prune must be conservative and should not be automatic in MVP.
```
